# Iterative Figure Workflow

Use this note when refining manuscript figures across multiple feedback rounds.

## Core Rules

### 0. Optimize first for clean, legible, orderly figures

Do not chase "fancy" as a default.

For manuscript figures, the minimum bar is:
- clean
- aligned
- uncluttered
- not visually thin
- readable without extra prose

Only pursue richer or more editorial encodings when they genuinely improve the message.

If a simple encoding:
- reads faster
- looks cleaner
- preserves the story

prefer it over a more ambitious but fragile design.

Practical rule:
- "fancy" is optional
- "clean and coherent" is mandatory

### 1. Draw from source data, not from cropped legacy PNGs

If an old figure is useful, reuse its logic, not its pixels.

Prefer:
- rerunning from source tables/arrays
- redrawing panels in a consistent current style
- building final panels from raw tables, ckpts, embeddings, or analysis outputs with a direct script path

Avoid:
- cropping old composite figures
- stretching raster panels
- mixing old typography with new typography
- using rendered PNGs as the final figure source

For manuscript delivery, distinguish two stages:
- preview stage: temporary contact sheets or collages are acceptable for internal review
- final stage: every approved panel and figure must be regenerated by script from traceable inputs

That script should be auditable back to:
- source tables / csvs / npzs
- ckpts or saved model outputs when relevant
- analysis code that computed the panel values

If a candidate figure cannot be traced back to raw inputs, treat it as provisional and rebuild it.

### 2. Keep embeddings geometrically honest

For UMAP, t-SNE, latent embeddings, or spatial manifolds:
- preserve equal aspect ratio
- do not stretch panels to fill layout slots
- leave enough top margin so titles do not overlap the point cloud

### 2b. Default manuscript canvas: white, vertical A4

Unless the user explicitly asks for another format:
- main figures should default to a white background
- use a vertical A4-like canvas ratio
- treat this as the starting page architecture for Nature/Methods-style results figures

Do not default to:
- landscape canvases
- dark backgrounds
- square collage layouts
- beige or tinted page backgrounds that make the figure feel off-brand unless the user explicitly asked for that mood

Only deviate when the figure's logic clearly demands it.

### 3. Verify benchmark completeness before showing a panel

Before exporting a benchmark panel:
- make sure every method has every displayed metric
- resolve missing values before designing the panel
- check whether suspicious ties are real or a merge bug

### 4. Let biology appear on the manifold when possible

If the figure's claim is biological:
- prefer showing the result on UMAP/latent/spatial coordinates
- do not rely only on bars or line charts
- use bars/lines as anchors, not as the only readout

### 5. Keep panel logic sequential, but do not force one template

For a strong main figure, panels should read as a coherent progression that serves the
figure's one-sentence claim.

A common default is:
- overview
- quantitative anchor
- biological structure
- mechanism / timing / interpretation

But this is only a starting pattern, not a rule.

Some figures should instead be:
- biology first, then mechanism
- mechanism first, then benchmark
- or almost entirely biological with only a small quantitative anchor

Avoid disconnected panel mosaics. The order should be determined by the figure's central
message, not by a fixed template.

Practical rule:
- panel letters should still follow the reading order on the page
- do not place `B` visually before `A`, or `C` before `B`, even if the conceptual hierarchy is different
- if the true hero is not panel `A`, restructure the page so `A` can still be the first readable block and the hero can be `B`

When a row is clearly stronger after being simplified into a clean anchor layout:
- keep that lesson
- do not re-complicate later rows just to make the page feel more "designed"

### 6. When two panels are conceptually linked, share the same visual variable

Examples:
- commitment-in-space should connect to commitment timing
- route groups in trajectory panels should use the same route colors in gene programs
- subcluster labels should recur downstream if they matter mechanistically

If two linked panels still feel disconnected after several revisions, the problem is often not
color. It is usually one of:
- the downstream panel is summarizing the wrong biological object
- the visual encoding is too abstract for the claim
- the figure is trying to show a story that the data do not support cleanly

In that case, change the representation early instead of polishing a weak encoding.

### 7. User approval workflow

For manuscript projects with an approval rule:
- candidate figures stay in `outputs/...` or analysis directories
- only approved figures/scripts go into manuscript `approved/`
- copy:
  - editable script
  - PDF
  - PNG

For approved figures, preserve the full editable chain where needed:
- final assembly script
- component panel scripts
- any helper script that transforms raw data into plotted tables

The approved directory should make it possible to re-run the figure from raw inputs without
depending on ad hoc notebook state or a previously rendered raster.

For supplement figures with multiple panels:
- export the full figure
- also export each panel as its own PNG/PDF crop from the scripted figure canvas
- save the script that generated both the full figure and the panel crops

### 8. Avoid IM cache confusion

When resending a revised figure to Feishu/Lark/IM:
- export to a new filename or versioned directory
- do not rely on replacing an old filename

### 9. Generate multiple variants early, converge late

For ambiguous panels such as benchmark summaries:
- generate several layout candidates first
- choose one direction
- then refine typography, spacing, and color

Do this especially when:
- the current panel uses only 2-3 marks and looks empty
- a bar chart feels thin or generic
- a mechanistic panel is not clearly tied to the biological claim

Common rescue move:
- switch from bars to gene-level tiles, dot matrices, or route-specific mini-panels
- keep the panel rectangular if it must sit beneath rectangular plots

When a panel still feels too ordinary after this:
- try richer but still structured encodings such as:
  - grouped tiles with module brackets
  - dot strips with aligned labels
  - ribbon or alluvial summaries
  - aligned cards with embedded quantitative marks
  - compact inset manifolds paired with one quantitative readout

Avoid defaulting to a plain heatmap if it does not add hierarchy or emphasis.

But also avoid the opposite failure:
- a forced "editorial" encoding that obscures the data
- a mechanism panel that becomes less interpretable than a clean violin, bar, box, ridge, or dose-response chart

When richer encodings keep failing, demote ambition:
- use the simplest sturdy grammar that still communicates the point
- then polish spacing, hierarchy, and typography

### 9b. Escalate after repeated disagreement

Do not get stuck in a private loop with a reviewer subagent.

If the same panel has gone through 10 substantial revision rounds and the reviewer still does not
approve it, stop the loop and send the current best version to the user for adjudication.

The reviewer is a critic, not the final authority.

### 10. Main-figure polish checklist

Before sending a candidate to the user, check:
- Is there an obvious hero panel?
- Are titles aligned and visually quiet?
- Is the page actually white?
- Do panel letters follow the visible reading order?
- Have I avoided adding descriptive prose sentences onto the figure itself unless the user explicitly asked for them?
- Are embedding panels unstretched?
- Are baseline methods visually subdued?
- Is the main method the easiest to track?
- Are weak/low-information panels removed?
- Does the figure read top-to-bottom or left-to-right without explanation?
- If all manifold panels are zoomed founder crops, have I included at least one full-context manifold or trajectory panel so the reader can orient the biology globally?
- Am I showing the biological object the story is actually about, rather than a proxy that only sounded plausible?
- For the top half of the page, have I made the large anchor panels genuinely large enough? Strong page architecture matters more than cramming in extra mini-panels.
- If the user responds much better to one row (`A/B/C`) than another (`D/E/F`), treat that as a layout lesson, not as local taste noise.
- Are row-internal panels explicitly aligned to meaningful outer anchors, rather than relying on default subplot spacing?
- If a bottom row contains two subplots, have I checked whether their left and right plot areas should align to the columns above?

### 11. Do not default to descriptive text blocks inside the figure

For manuscript main figures:
- do not automatically add sentence-style explanatory text above or inside the figure
- prefer short panel titles, route labels, or module labels only
- put explanatory prose in the caption, not on the canvas
- if a panel still feels unclear, fix the encoding first instead of pasting a new explanatory sentence onto the figure

Only add descriptive text blocks when:
- the user explicitly asks for them
- a small schematic absolutely needs one short setup label
- the figure would otherwise be ambiguous even after panel labeling

### 12. Preserve editability at every approved stage

When a panel is approved:
- save PNG and PDF
- save the exact script that generated the approved version
- when the panel depends on reusable upstream helper scripts, keep those too

Do not assume the combined figure script alone is enough for later manual edits.

### 13. Do not over-invest in a weak panel concept

Warning signs:
- the user keeps asking what the panel means
- the panel needs long verbal justification
- a reviewer repeatedly says the structure is not visible
- multiple encoding tweaks do not change the basic readability

When these appear:
- pivot to a more direct biological object

### 14. Avoid table-like mechanism panels in main figures

Do not default to:
- grids of small rectangles with one number per cell
- heatmap-like tiles that read like a spreadsheet rather than a visual story

These may be acceptable for supplement, but in a main figure they often fail because:
- the reader parses them as a table, not as a picture
- they do not reveal directionality or contrast at a glance
- they usually require narration to be understood

Prefer instead:
- dumbbell or lollipop comparisons across states
- dose-response line plots
- ridge/violin summaries
- aligned gene-level dot strips
- small multiples where each subpanel has a clear visual shape
- clean bar or box summaries when the underlying question is simple and directional

Heatmaps are still acceptable when:
- there is a true dense matrix pattern to read
- color carries the primary structure
- the panel does not collapse into a few isolated tiles with printed numbers

If the user says a panel feels like a table, believe them and change the grammar.

### 15. Large anchor panels should dominate early rows

For the top half of a main figure:
- use one or two large anchor panels that set orientation and mood
- do not make them the same visual weight as a later support block
- if a row feels much cleaner after replacing a busy panel with one strong square/rectangular anchor, keep that lesson

Typical good pattern:
- row 1: two large anchors of comparable size
- row 2: one wide compare row
- lower rows: more detailed biology/mechanism blocks

### 16. Peer panels usually read better side-by-side

When two or three panels in the same row are peers:
- align their outer plot boundaries
- equalize visual weight where appropriate
- use explicit subplot placement if automatic grids leave them visibly off

For rows that should span the same page width:
- make the exported panel aspect ratio compatible with the assembly slot
- do not rely on a preview stitcher to fix a panel whose native aspect ratio is wrong

### 17. Use visual diversity across a main figure, but keep it disciplined

A strong main figure often benefits from several distinct plot grammars, for example:
- one manifold / embedding panel
- one comparison row
- one distribution panel
- one temporal or perturbation panel

But diversity should come from function, not decoration.

Bad diversity:
- every panel uses a different aesthetic just to look impressive

Good diversity:
- different biological questions use the most natural visual grammar

If the page already has enough variety, do not force later panels to look novel.

If two panels are at the same narrative level:
- prefer placing them side-by-side in one row
- let the reader compare them left-to-right

Do not stack peer panels vertically unless:
- the shared x-axis or timeline genuinely demands it
- or the user explicitly wants a vertical dependency

Typical example:
- `D` and `E` as two sibling support blocks should usually be horizontal neighbors, not a vertical ladder

### 17. Split complex mechanism blocks into horizontal companions

If one panel concept naturally contains two distinct readouts:
- do not force them into one stacked mini-dashboard under a single cramped header
- consider making them a horizontal pair with one shared letter and two quiet subtitles

This often works better for:
- regulator support + perturbation response
- model support + experimental support
- state summary + dose-response summary

Reason:
- the reading path stays left-to-right
- titles collide less
- the figure feels designed instead of jammed
- demote the panel to supplement
- or replace the proxy with the actual case/result the figure wants to show

Do not keep polishing the same weak concept indefinitely.
